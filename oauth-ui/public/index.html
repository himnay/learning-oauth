What happens

  1. Server creates a random code_verifier and its SHA-256 code_challenge.
  2. Browser is redirected to Keycloak with the code_challenge, state and nonce.
  3. You log in on Keycloak; it redirects back to /callback?code=…&state=….
  4. Server checks state, then POSTs code + code_verifier to the token endpoint.
  5. Keycloak hashes the verifier, compares with the stored challenge, and issues tokens.
  6. Server verifies the ID token signature (JWKS), issuer, audience and nonce.
  7. The page asks this server to call the Spring Boot oauth-keycloak; the server sends the access token as Authorization: Bearer ….
  8. Spring Security validates the JWT (signature, expiry, issuer, audience, role) and the API returns its result.
